# 笔记风格指南

目标是让几个月后的自己能快速找到问题、理解结论、复现过程。先把内容写完整，再整理排版，不必每篇都套满所有章节。

## 1. 从三种模板开始

| 笔记类型 | 适合记录                       | 模板                               |
| -------- | ------------------------------ | ---------------------------------- |
| 知识概念 | 原理、术语、架构与对比         | [概念笔记](templates/concept.md)   |
| 控制算法 | 输入输出、计算过程、示例与调参 | [算法笔记](templates/algorithm.md) |
| 问题记录 | 环境、复现、证据、定位与验证   | [问题记录](templates/issue.md)     |

复制模板到 `docs` 对应分类，改文件名、`title`、`permalink`，删除用不到的章节与占位文字。模板放在 `writing`，不会成为网站文章。

## 2. 标题与开头

文件头写 `title`；正文从 `##` 开始，网站会自动显示文章主标题。新笔记不必手工写章节序号，使用 `##`、`###` 表达层级，避免从二级直接跳到四级。

第一段用两三句话说明“记录什么、解决什么问题、在什么条件下适用”。短篇笔记可以直接进入主题。

已有文章的标题可能被别人用作章节链接。ESC 示范保留原章节名称与编号，以保留历史链接；改标题前应检查链接兼容。

## 3. 段落、列表与强调

- 一段表达一个意思；解释因果与原理时优先使用完整段落。
- 并列项目用列表，操作和复现顺序用有序列表，对比多个对象用表格。
- 提示读者重点时使用少量加粗。参数名、寄存器名、状态名使用行内代码，如 `GAIN`、`ModuleReady`。
- 分割线留给明显的内容边界，普通章节靠标题分隔即可。
- 引用块适合简短直觉或原文引用；事实、推测、待验证结论要在文字里标清。

## 4. 图片、表格、代码和公式

图片独立成段，提供能描述图片的说明；图片下方可补一句图注。保持原相对路径，不为排版重命名已发布的图片。

```markdown
![采样与更新的状态切换](./assets/状态切换.png)

图 1：每累计 N 次采样后，更新一次控制量。
```

表格回答一个明确的对比问题，列数尽量少。表格内容太长时，拆成说明段落与简表。

可运行代码标明语言，例如 `c`、`python`；状态流与日志使用 `text`。说明文字通常放在代码块外，代码块前交代用途，后面交代观察结果。自动排版保留代码内容；缩进、参数、计算顺序或代码逻辑的修改应单独审阅。

行内公式使用 `$...$`，独立公式使用单独两行 `$$`。公式旁写清符号、单位、适用条件。自动排版若会改变公式，会停止该文件的写入并提示人工检查。

## 5. 技术内容怎样审阅

审阅意见固定分为三类：

1. **格式问题**：空行、列表、图片位置、代码语言等，可整理。
2. **表达建议**：结构、重复、术语解释等，给出修改前后对照。
3. **技术疑问**：算法假设、边界条件、数值、寄存器含义等，列出依据与待确认问题，不擅自改结论。

算法笔记优先写清输入输出、参数含义、更新条件和观察结果。问题记录优先保留版本、复现步骤、日志证据以及修复后的验证结果。原理笔记区分资料来源与自己的推断。

示范：[ESC 笔记](../docs/embedded/control_algorithm/esc.md)。审阅意见：[ESC 风格审阅](reviews/esc.md)。

## 6. 写完后的操作

在项目目录运行：

```powershell
npm run notes:format
npm run notes:check
```

默认处理新建或相对原文基线改过的普通笔记，未改动的存量笔记不强制整改；Windows／Linux 换行差异不会被当作内容改动。基线包含首次发布时同步的远程笔记。也可以明确指定一篇：

```powershell
npm run notes:format -- "docs/embedded/control_algorithm/esc.md"
npm run notes:check -- "docs/embedded/control_algorithm/esc.md"
```

排版会整理空行、列表、表格等，保留围栏代码与公式。标题层级、缺少图片说明等问题会报告位置，需根据意思调整。排版成功不表示技术内容正确。

在这个聊天中使用 [审阅提示词](review-prompt.md)，让助手检查本次改动。最后运行 `npm run build`、`npm run verify`，在本地网站看一遍，再提交并推送。GitHub Actions 自动执行格式检查，失败时不会部署；它不会自动调用 AI，也不会自动修改你的文章。

配置来源：[Prettier 选项](https://prettier.io/docs/options)、[markdownlint](https://github.com/DavidAnson/markdownlint)。项目选择保留正文换行、关闭嵌入代码自动排版，并额外保护代码块和公式。
